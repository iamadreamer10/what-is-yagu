## F1 야구 정보

### 목적
뉴비가 가장 많이 막힌 숫자·기록(10/17), 팀·선수(8/17), 응원 문화(8/17), 용어(7/17)를 짧고 치우치지 않게 풀어 준다. 고인물이 "가장 먼저 알면 좋은 것"으로 꼽은 규칙(13/15)은 야구 기본에서 먼저 알려 준다.

### 사용자 흐름
1. 홈에서 묶음을 고른다: 야구 기본 / 리그 운영 / 기록 읽는 법 / 팀·선수
2. 야구 기본: "누가"(투수·타자·주자·야수·심판·벤치·관중석)로 묶인 목록 → 문서 하나 (정의, 짧은 풀이, 이런 장면에서, 밈)
3. 기록 읽는 법: 기준표 (예: 타율 .300 이상 = 3할 타자) → "한 단계 더"(OPS·WAR)
4. 팀·선수: 팀 목록 → 팀 상세 (특징, 응원 문화, 홈구장, 주요 선수) / 부문별 TOP 5 → 선수 기록에 등급과 한 줄 → 선수 이름을 누르면 네이버 검색 새 탭

### 들어갈 것
- 야구 기본: 규칙, 용어(타격·투구·주루·작전), 경기 흐름, 포지션. 한 개념에 한 문서, "누가"·"감정" 꼬리표 (D-049, D-053)
- KBO 리그 운영 정보: 구단 수, 정규시즌 구조, 순위 방식, 가을야구, 일정
- 기록 읽는 법: 1차 스탯 기준표(타자·투수 각 4~5개), 규정타석·규정이닝 설명 (D-048)
- 팀 정보 10개 구단: 특징, 응원 문화, 홈구장(대표 먹거리 몇 줄), 팀 색상
- 선수 기록: 타자 8개·투수 7개 부문 TOP 5, 2026 시즌 확정 기록 (D-049)

### 뺄 것
- 사진·로고·응원가 가사 (권리), 실시간 순위·경기 결과 (KBO 링크로 대신), 크롤링 (D-047), 구장 먹거리 평점 (Backlog)

## F2 재미로 정해 보는 응원팀

### 목적
뉴비가 마음이 식은 이유 2위가 "응원할 팀이 없어서"(5/17)였고, 고인물이 계속 본 이유 1위는 "마음에 드는 팀·선수"(12/15)였다. 정답을 주장하지 않고, 재미로 나와 맞는 팀을 알아보게 한다 (D-007, D-050).

### 사용자 흐름
1. 시작 → 질문 6~8개에 답한다 (예: 사는 곳, 좋아하는 분위기, 강팀/언더독 취향)
2. 결과: 나와 맞는 팀 1~3개와 이유 한 줄 → 팀 상세(F1)로 이동

### 팀 성향 기준의 근거 (상세 명세에서 정한다)
- 설문에서 뉴비를 계속 보게 만든 것: 응원 분위기 8/17, 같이 보는 사람 8/17, 먹거리·나들이 같은 야구장 경험 7/17 → 분위기·구장 경험·함께 보는 사람이 축 후보다.
- 처음 함께 본 사람: 가족 10/17, 친구 7/17 → "함께 보는 사람의 팀"도 고려할 거리다.
- 고인물을 계속 보게 만든 것: 마음에 드는 팀·선수 12/15 → 좋아하는 선수 스타일도 축 후보다.
- 설문이 응원팀을 정한 이유를 직접 묻지는 않았지만, 문항을 더하지 않고 지금 설문으로 충분하다고 본다 (나, 2026-11-17). 축은 위 근거와 내 경험으로 세운다.

### 들어갈 것
- 질문과 선택지, 선택지별 팀 점수 (내가 정함), 점수 계산은 프로그램
- 결과에 "재미로 보는 결과예요" 안내

### 뺄 것
- 로그인, 결과 저장·공유 (MVP 이후), 평가 대상에서 제외 (D-007)

## F3 상황 검색

### 목적
뉴비는 "뭐라고 검색해야 할지 몰랐다"(4/17). 장면을 자기 말로 적으면 내가 쓴 F1 문서를 찾아 준다. AI는 뉴비의 말을 알아듣는 데 쓰고, 설명은 내 문서에서 나온다 (D-051, D-053, D-054).

### 사용자 흐름
1. 채팅 입력창에 장면을 적는다 (예시 질문을 보여 준다)
2. 질문 다듬기: AI가 야구 말 검색어로 바꾸고, 애매한지·범위 밖인지 판단한다
3. 결과
   - 찾음: "이 장면이 맞나요?" 후보 + 문서 카드 (②에서는 1~2문장 답 + 근거 카드)
   - 애매함: "어떤 장면이었나요?" → "누가" 고르기 → 필요하면 감정 한 번 더 (되묻기 최대 2번)
   - 범위 밖·못 찾음: 모른다고 답하고 F1 둘러보기로 안내. 질문은 이름 없이 모은다

### 들어갈 것
- ① 의미 검색: F1 문서(장면 예시 포함)를 임베딩해 pgvector로 찾기 (D-019)
- 질문 다듬기, 애매함·범위 판단 (가벼운 모델)
- ② RAG: 찾은 문서만 넘겨 짧은 답 생성, 근거 카드 항상 표시, 검색 점수가 기준보다 낮으면 LLM을 부르지 않음 (principles 4.1)
- 질문 로그: 질문, 다듬은 검색어, 찾은 문서와 점수, 결과 종류, 사용 토큰
- 요청 제한과 월 예산 상한 (principles 4.1)
- 평가 질문 세트로 L4(검색)·L5(답) 평가 (D-028)

### 뺄 것
- 오늘 경기 결과, 선수 근황, 승부 예측, 야구 밖 질문 / 이미지·영상 생성 (확장판)
- 고민 중: 내 질문 내역 저장 (사용자 구분이 필요하다. 로그인 또는 브라우저 저장)

### 시간 예산과 비교

주당 투입은 20시간 안팎이다 (나, 2026-11-17).

| --- | --- | --- |

필요한 시간(약 90~115h)보다 모자랄 수 있다. 다만 위 규모 표의 콘텐츠 시간은 문서 개수로 어림한 것이라 믿기 어렵다 (나, 2026-11-17). 콘텐츠의 품은 개수가 아니라 "어디까지, 얼마나 정성스럽게"를 정하는 데서 든다.

- 범위·기준을 정하는 일(규칙 범위, 리그 설명 범위, F2 팀 성향 기준)은 개발이 아니라 설계다. 각 기능 상세 명세(2-4, 2주차)에서 정한다.
