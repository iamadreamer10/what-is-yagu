# decisions.md (주제 확정)

> 이 작업 단위의 결정. 번호(D-000)는 프로젝트 전체에서 이어 매긴다. 한 번 기재된 결정은 지우지 않고, 바뀌면 상태만 "대체됨"으로 바꾼다.
> 출처: 나 / AI / 스터디원 · 영향도: 낮음 / 중간 / 높음

---

## D-001 개인으로 진행한다
- 날짜: 2026-11-07
- 상태: 유효
- 문제: 사이드 프로젝트를 팀으로 할지 개인으로 할지 (출처: 스터디 회의 / 영향도: 높음)
- 옵션: 팀 / 개인
- 선택: 개인
- 근거: 얻고 싶은 것이 "기획/설계부터 AI 활용 판단까지 전부 내 결정"이라는 근거다. 팀으로 하면 양보할 것이 많고, 팀 프로젝트는 이미 여러 번 했다. 협업·피드백은 주간 발표로 보완한다.

## D-002 6주(2주 기획/설계 + 4주 개발), MVP만 만든다
- 날짜: 2026-11-07
- 상태: 유효
- 문제: 기간과 진행 형식 (출처: 스터디 회의 / 영향도: 높음)
- 선택: 2주 계획, 4주 개발. 매주 진행 상황과 트러블슈팅 1건 발표
- 근거: 스터디에서 합의한 형식

## D-003 목표 우선순위를 정한다
- 날짜: 2026-11-09
- 상태: 유효
- 문제: 이 프로젝트에서 무엇을 가장 얻고 싶은가 (출처: 나 / 영향도: 높음)
- 선택: ① 기획/설계를 새로운 방식으로 준비 ② 서비스에 AI 기능 넣기 ③ 같은 조건이면 금융 (필수 아님)
- 근거: 개발은 AI에 많이 맡길 수 있으니 힘줄 곳은 도메인·기능 정의다. CRUD 위주 프로젝트는 이미 많이 해봤다.

## D-004 소상공인·중소기업 전자증빙(후보 B)을 제외한다
- 날짜: 2026-11-11
- 상태: 유효
- 문제: 최종 후보 압축 (출처: AI 비교 → 나 결정 / 영향도: 중간)
- 옵션: A 야구 입문자 / B 전자증빙 / C 거래 요청 해석기(이후 "나가는 돈 미리 알려 주기"로 변경)
- 선택: B 제외
- 근거: 결과물이 단순하고, 비슷한 서비스(경리나라, 비즈플레이 등)가 이미 많으며, 금융 연결도 "직결"이 아니라 "인접"이다. 동력도 A보다 낮다.
- 참고: 이 전에 약관·상품설명서 Q&A, 사회초년생 주거(전/월세) 대출, 카드·대출 구조 이해 서비스를 검토했고 보관했다.

## D-005 주제를 C(자동으로 나가는 돈 미리 알려 주기)로 확정한다
- 날짜: 2026-11-11
- 상태: 대체됨 (D-006)
- 문제: 최종 주제 (출처: 나 / 영향도: 높음)
- 옵션: A 야구 입문자 / C
- 선택: C
- 근거: 은행이 하려는 방향(거래 요청 해석기)을 가져온 게 아니라, 자동이체·카드 대금·구독 때문에 잔액을 머릿속으로 계산해야 하는 불편을 직접 겪었다. 금융에 직결되고, 가상 거래 내역에 정답 라벨을 심어 측정할 수 있다. AI는 거래 카테고리화로 시작한다.

## D-006 주제를 A(야구 입문자 서비스)로 변경한다
- 날짜: 2026-11-12
- 상태: 유효
- 대체: D-005
- 문제: 스터디 회의에서 A에 대한 반응이 좋았다 (출처: 스터디원 → 나 결정 / 영향도: 높음)
- 옵션: C 유지 / A로 변경
- 선택: A로 변경, C는 다음 프로젝트 후보로 보관
- 근거:
  - 20년 본 도메인이라 AI가 만든 설명이 틀린 곳을 내가 직접 잡아낼 수 있다. AI와 같이 기획/설계를 해도 검증과 주도권이 내게 있다.
  - 입문자가 막히는 지점, 설명 순서, 근거 문서 범위를 직접 정의해야 해서 기획/설계를 탄탄하게 가져갈 수 있다.
  - 은행 면접을 본 스터디원에 따르면, 금융 도메인이 아니어도 AI를 적극적으로 쓴 프로젝트에 관심이 많았다.
  - 6주를 혼자 끌고 갈 동력이 가장 크다.

## D-007 응원팀 정하기는 재미 콘텐츠로 둔다
- 날짜: 2026-11-12
- 상태: 유효
- 문제: 응원팀 정하기의 위치 (출처: 나 / 영향도: 중간)
- 선택: 메인 기능이 아니라 뉴비가 재미로 해 보는 참고용 콘텐츠. 평가 대상에서 뺀다.
- 근거: 응원팀에는 객관적 정답이 없다. 나도 야구를 10년 정도 보고 나서야 응원팀을 정했다.

## D-008 금융 기능은 확장판에서 생각한다
- 날짜: 2026-11-12
- 상태: 유효
- 문제: 금융과 어떻게 연결할까 (출처: 스터디원 제안 "출석 등으로 회원 등급을 매겨 스킨을 바꾸게 하면 어떨까" → 나 판단 / 영향도: 낮음)
- 옵션: MVP에 금융 성격의 기능을 붙인다 / 확장판으로 미룬다
- 선택: 확장판으로 미룬다. 등급·스킨 제안은 보류
- 근거: 억지로 붙인 연결은 도메인 이해의 근거가 되지 않는다. 같은 설계를 금융 문서에 옮겨 보는 실험과 면접 설명으로 연결한다.
